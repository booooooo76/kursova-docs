# Регламент підтримки документації

Документація — не разовий артефакт, а частина системи. Застаріла документація небезпечніша за відсутню: вона
створює ілюзію розуміння. Тому кожен документ продукту має власника, цикл перегляду й тригери, що вимагають його
оновлення.

## 1. Головне правило

> **Зміна коду = зміна документації.** Жодна зміна не потрапляє в основну гілку, якщо вона змінює поведінку,
> маршрути, схему даних, конфігурацію чи порядок розгортання, а зачеплені документи не оновлено в тому самому
> коміті або pull request.

Як це забезпечено:

1. **Ворота** `tools/doc_currency.py` (код виходу 1 = FAIL): шукають код, змінений після останнього коміту документа,
   JSON-маршрути, яких немає в SDD, і прострочені перегляди.
2. **Чекліст pull request** (`.github/pull_request_template.md`): автор підтверджує, які документи оновив.
3. **Цикл перегляду**: навіть без змін коду документ переглядається за графіком і отримує нову дату `last_reviewed`.

## 3. Тригери: яка зміна коду вимагає якого документа

Ті самі правила записані в `DOC_RULES` у `tools/doc_currency.py`.

| Змінено | Оновити |
|---|---|
| `app.py`, `routers/` (маршрути, ролі) | README (якщо змінилася поведінка для користувача), SDD §3 і §5 |
| `services/`, `privacy/`, `models/` | SDD §3 і §5.4; для `privacy/` ще політики `docs/lab4/` і ADR-0002 |
| `migrations/`, `tests/db/schema_base.sql` | SDD §4 (модель даних), ISD §3.2 і §4 |
| `config.py`, `.env.example` | ISD §2 (змінні), README (швидкий старт) |
| `app.py` (точка входу), `scripts/migrate.py`, `requirements.txt` | ISD §3–4 (запуск, порядок підняття) |
| `.github/workflows/`, `.githooks/`, `sonar-project.properties`, `scan.ps1` | ISD §5 (CI і ворота) |
| нове архітектурне рішення | новий ADR з наступним номером; старий отримує статус Superseded |

## 4. Процедура

1. Перед злиттям: `.\venv\Scripts\python.exe tools\doc_currency.py`. Для злиття потрібен `RESULT: PASS`.
2. Під час перегляду за графіком власник читає документ проти коду, виправляє розбіжності й оновлює `last_reviewed`
   у шапці документа та в таблиці розділу 2.
3. Раз на квартал повторюється аудит Завд.1: `.\venv\Scripts\python.exe tools\doc_audit.py --tag <квартал>`.
4. Застарілий документ не редагується «заднім числом»: його переносять у `docs/archive/` з позначкою DEPRECATED.

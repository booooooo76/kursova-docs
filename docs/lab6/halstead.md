## 2. Що таке оператор і операнд (і чому інструменти дають різні числа)

За методичкою **оператор** це те, що *діє*: ключові слова (`if`, `for`, `return`, `def`), знаки операцій (`+`, `==`, `=`)
і роздільники (`(`, `)`, `,`, `:`, `.`). **Операнд** це те, *з чим* діють: імена змінних, константи, рядки, аргументи.

Приклад, порахований вручну і перевірений `tools/halstead_classic.py`:

```python
def area(w, h):
    if w > 0:
        return w * h
    return 0
```

| | Токени | Унікальних | Усього |
|---|---|---|---|
| Оператори | `def ( , ) : if > : return * return` | η₁ = 9 (`def ( , ) : if > return *`) | N₁ = 11 |
| Операнди | `area w h w 0 w h 0` | η₂ = 4 (`area w h 0`) | N₂ = 8 |

Три інструменти по-різному визначають оператор, тому їхні числа відрізняються:

| Інструмент | Що вважає оператором | Глобальне η₁ проєкту |
|---|---|---|
| multimetric | знаки операцій і роздільники (23 унікальних) **плюс імена** функцій, класів, декораторів, винятків (250) | 273 |
| класичний лічильник (методичка) | ключові слова + знаки операцій + роздільники | 48 |
| radon hal | лише знаки операцій у виразах (`+`, `==`, `and` …), без ключових слів і роздільників | (лише по файлах) |

Тому абсолютні числа порівнюємо лише в межах одного інструмента, а висновки перевіряємо всіма трьома.

## 5. Математичний доказ: менше рядків, але більше зусиль

`policy.py` довший за `consent.py` за будь-якою мірою рядків (302 проти 195 за multimetric, 335 проти 272 фізичних,
288 проти 173 SLOC), але потребує **майже вдвічі менше** зусиль.

| | `privacy/consent.py` | `privacy/policy.py` |
|---|---|---|
| Словник η = η₁ + η₂ | 40 + 94 = 134 | 18 + 52 = 70 |
| Довжина N = N₁ + N₂ | 700 + 447 = 1 147 | 940 + 302 = 1 242 |
| Об'єм V = N · log₂η | 1 147 · 7,066 = **8 104,8** | 1 242 · 6,129 = **7 612,6** |
| Складність D = (η₁/2) · (N₂/η₂) | 20 · 4,755 = **95,11** | 9 · 5,808 = **52,27** |
| Зусилля E = V · D | **770 819** | **397 903** |

Об'єм майже однаковий (різниця 6%), тобто «кількість тексту» схожа. Усю різницю дає складність D, а в ній множник
η₁/2: у бізнес-модулі 40 різних видів операцій (порівняння, логічні оператори, виклики, винятки, блокування), у
реєстрі лише 18, бо він складається з однотипних оголошень. Програміст, що читає `consent.py`, мусить тримати в голові
у 2,2 раза більше різних дій. LOC цього не бачить взагалі: у формулі E рядків немає, а є лише різноманіття й
повторюваність токенів.

## 7. Інженерний висновок (code review)

1. **Роль коду визначає зусилля.** Бізнес-логіка (`consent.py`) насичена різними видами рішень, тож має найвищу
   складність D (95) і найвищі зусилля серед трьох. Інфраструктурний `database.py` маленький (V = 2 352) і помірно
   складний (D = 27). Декларативний реєстр `policy.py` довгий, але одноманітний (D = 52).
2. **LOC приховує проблеми.** Якби ранжувати за рядками, найскладнішим із трьох виявився б `policy.py`, а реальний
   hotspot `consent.py` опинився б посередині. У масштабі проєкту так само: `sanitizer.py` (171 рядок) і `consent.py`
   (195) мають більші зусилля, ніж `admin.py` (277) чи `pc_builder.py` (266), а за щільністю зусиль на рядок вони вищі
   навіть за `sql_queries.py`, хоча коротші за нього в 3–4 рази.
3. **Великі файли домінують в абсолютному E**, бо зусилля ростуть швидше за розмір: перші чотири місця займають
   найбільші файли. Щоб знайти щільні модулі серед невеликих, корисно дивитись і на E на рядок.
4. **Числа залежать від визначення оператора** (п. 2), тож порівнювати можна лише в межах одного інструмента.
   Висновок «бізнес-модуль найдорожчий для розуміння, а LOC це ховає» тримається за всіма трьома інструментами.

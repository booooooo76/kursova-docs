## 2. Контрольована зміна (FAIL, `ebc5e0c`)

Новий API-ендпоінт `GET /api/health` (перевірка готовності: БД + міграції), документи не змінено:

```diff
 app.py               |  3 +++
 routers/health.py    | 46 ++++++++++++++++++++++++++++++++++++++++++++++
 tests/test_health.py | 39 +++++++++++++++++++++++++++++++++++++++
+from routers.health import health
+app.add_url_rule('/api/health', 'health', health, methods=['GET'])
```

Код коректний: 3 нові тести зелені, хук pre-commit пропустив коміт (секретів немає, CC ≤ 10). Тобто звичайні ворота
якості коду цей дефект **не бачать**: зламалась не програма, а знання про неї.

Вік документа в цьому експерименті не встиг зрости: зміна й виправлення відбулися в один день. Саме тому вік — слабкий

документа** (поріг 0 для паспорта, а не 20 з аудиту) і на звірку структури (маршрути в коді проти SDD).

## 6. Висновок

Код пройшов усі ворота якості коду, а документація трьох аудиторій стала хибною одним комітом. Без воріт документації
дрейф помітили б лише тоді, коли новачок чи DevOps діяли б за інструкцією, якій більше не можна вірити. Правило
«зміна коду = зміна документації» спрацювало, лише коли його перевіряє машина: `doc_currency.py` дав FAIL зі списком
документів і точним маршрутом, а після оновлення трьох документів — PASS.

## 5. Досяжність інших знахідок

- **flask CVE-2026-27205.** Flask не додає заголовок `Vary: Cookie`, якщо до `session` звертаються через оператор `in`. Експлуатується лише коли застосунок стоїть за кешувальним проксі без `Cache-Control: private`. Застосунок запускається напряму (`python app.py`) без проксі — у поточному розгортанні не експлуатується, але виправлено оновленням.
- **werkzeug (3 advisory).** Усі про `safe_join()` та імена пристроїв Windows (`CON`, `NUL` тощо), вплив — Availability:Low. Маршрут `/static/<path:filename>` у застосунку існує (`send_from_directory` → `safe_join`), тож функція досяжна, але тільки на Windows. Прямих викликів `safe_join`/`send_from_directory` у коді немає. Виправлено оновленням.
- **idna CVE-2026-45409.** DoS через спеціально сформований довгий вхід у `idna.encode()`. `idna` потрапляв у runtime лише через `email-validator`, який у коді не використовується (`import email_validator` відсутній, як і `flask_wtf`, `wtforms`, `flask_sqlalchemy`, `sqlalchemy`). Тому замість оновлення прибрано сам непотрібний ланцюг залежностей.

## 8. Область перевірки та залишковий ризик

Аудитується **декларований набір залежностей застосунку** (`requirements.txt`). Службові пакети самого venv (`pip`, `setuptools`) та dev-інструменти (`requirements-dev.txt`: radon, pip-audit тощо, а з ними `requests` → `idna`) не входять у поставку застосунку. Усе одно для чистоти локального середовища їх можна оновити:

```
python -m pip install -U pip setuptools idna
```

Після цього і «голий» `pip-audit` (без `-r`) по venv дає `No known vulnerabilities found`.

Прийнятих ризиків і винятків немає. Якби вразливість довелося приймати, вимоги такі: advisory ID, доказ недосяжності у коді, компенсувальний контроль, дата перегляду.
